# BlueArchiveMiniGame 开发与资源使用指南

更新于 2026-10-28。本指南对应当前四前排、两支援的小队战斗 Demo，替换旧单人移动射击与旧资源驱动说明。长期玩法与后续阶段以同目录的《系统需求文档 v0.3》《游戏策划案 v0.3》为准。

## 运行当前 Demo

打开 `Assets/GameRes/Scenes/Player_GameDev.unity`，直接 Play。先在编队页选择、拖动四名前排，再点击出击。前排为天童爱丽丝、才羽绿、才羽桃井、花冈柚子；两个支援位为花冈柚子（女仆）与花冈柚子（临战）。前排与支援在各自组内换位。

第一名前排是队长。入场随机播放该队长自身已配置的两条原出场语音之一；胜利仍从存活前排中随机选出演出领队。提起学生使用原提起动作和语音，单选学生下达移动命令时播放其移动语音。编队页已使用三维角色，但不代表原版编队的全部业务功能都已复原。

| 操作 | 当前行为 |
| --- | --- |
| 左键点选或框选，Shift 追加 | 选择前排单位 |
| 数字 1–4，数字 5 | 单选对应前排，全选 |
| 右键地面，右键敌人 | 移动，指定集火 |
| Alt + 右键 | 攻击移动 |
| H，X | 停驻，恢复自动行为 |
| F1–F4 | 四名前排 EX |
| F5 | 女仆柚子支援炮击 |
| 先选前排再 F6 | 给该前排施加临战柚子支援 |
| Space | 战术暂停 |
| WASD／鼠标中键拖动，滚轮 | 平移战场镜头，缩放 |

右下六张技能卡也可点击。当前不是原版 COST 抽牌系统。暂停中可选择、下达移动命令，但不能施放 EX。

所有存活前排进入绿色撤离圈，播放完刹车并停稳，连续保持 3 秒才胜利。圈中心 `(0, 0, 13)`、半径 3 米；有人离圈或再移动会重置计时，暂停和 EX 过场冻结计时。清敌本身不触发胜利。撤离成功显示原 VICTORY 标题，再播放四名前排胜利演出与 Complete 结果层。敌人目前只有生命和碰撞，没有敌方 AI。

## 目录与接入边界

| 目录 | 用途 |
| --- | --- |
| `Assets/GameFramework` | 不依赖具体玩法的框架代码 |
| `Assets/GameScript/Runtime` | 游戏启动与不能热更的代码 |
| `Assets/GameScript/HotUpdate/Preload` | 预加载热更程序集 |
| `Assets/GameScript/HotUpdate/Main` | 当前角色、小队与 UI 逻辑 |
| `Assets/GameScript/Editor` | 资源整理、装配与编辑器工具 |
| `Assets/GameScript/Test`、`Tests` | 现有试验与测试内容，不是游戏入口 |
| `Assets/HybridCLRGenerate` | HybridCLR 生成内容 |
| `Assets/GameRes/Characters` | 按人物与形态分类的模型、动画、材质、音频和演出 |
| `Assets/GameRes/Battle` | 当前小队的配置、预制体、派生动画、界面和演出 |
| `Assets/GameRes/Scenes` | 当前游戏场景 |
| `Assets/GameSetting` | 渲染、音频、YooAsset 等项目设置 |
| `Assets/ThirdParty`、`Plugins` | 第三方代码与原生插件 |

基础角色入口是各人物 `Prefabs` 下的完整模型 Prefab；Avatar 只是骨架描述，不是模型入口。`Prefabs/Preview` 内为带技能演出的预览对象。当前小队实际使用 `GameRes/Battle/Characters` 中已装配的单位，不应把仅有模型的 Prefab 直接当成完整战斗单位。

游戏开发部资源包含 10 个形态：四个普通、四个女仆、爱丽丝临战、柚子临战。当前小队 Demo 的候选阵容仍是前述 4＋2，并不表示全部 10 个形态都已作为可选战斗单位接入。两位支援不常驻地面，不加入前排导航、生命或撤离人数统计；不为没有原普攻的支援编造射击动作。

## 从哪些类开始读

以下七个类位于 `Assets/GameScript/HotUpdate/Main/Battle`。

| 类 | 负责什么 |
| --- | --- |
| `BattleSession` | 组织编队、入场、统一 Tick、暂停、支援、撤离和胜败；管理本局投射物 |
| `SquadInput` | 接收选择与命令，处理编队操作和 uGUI；把意图交给单位 |
| `CharacterUnit` | 保存每名学生的命令、目标、弹药与行动状态，决定移动、刹车、攻击、换弹和 EX |
| `CharacterDefinition` | ScriptableObject：角色属性、原动作时序、演出与语音引用；不保存局内可变生命和弹药 |
| `BattleProjectile` | 推进已发射弹体并提交有效命中 |
| `Health` | 生命与存活状态，接收逻辑伤害 |
| `SquadCamera` | 战场平移缩放、探索与战斗视角以及演出镜头衔接 |

角色表现代码仍在 `Main/Player`：`Presentation/BACharacterPresentation` 组织 Animator 和 EX；`CharacterCombat` 处理已有枪口、声音、目标型弹体等表现；`CharacterSkillData` 保存技能配置；`ExCameraTransition` 负责原擦屏及镜头交接。`Main/Managers` 内的 `AudioManager`、`EffectManager` 负责声音和特效实例，不拥有伤害、弹药或胜败规则。

`BACharacterController` 是单角色试玩输入入口，当前小队由 `SquadInput → CharacterUnit` 驱动；不要让两套输入同时控制同一个模型。主相机留在场景中，角色演出只在需要时接管并归还相机。

普通攻击由原生动画事件通知开火，逻辑命中仍通过 `BattleProjectile → Health` 提交，不能再从视觉碰撞或音效回调扣一次血。连续射击保留 Start、Ing、Delay 链路，只停止继续射击时走 End 再回 Idle。抵达移动目标先播原刹车，不直接跳待机。

## 2026 年 10 月 28 日动画修复

本轮检查 10 个资源形态的移动、刹车、攻击、换弹和战场 EX 回待机，采样实际控制器并复看可疑段画面。支援没有的攻击链路不计为“攻击通过”。

- 普通柚子：修正普攻入口及攻击链的零时长切换；派生普攻片段改为单次播放，避免混合时绕回开头。战斗控制器和角色预览控制器同步处理。
- 普通小绿：延续此前普攻切换修复，补修进入换弹与换弹结束回待机的硬切。
- 柚子攻击与小绿换弹入口采用原普通攻击行为的缺省混合值 `4/30`，它是 normalized transition duration，不是固定 0.133 秒。原武器状态表的显式规则优先，不能把这一数值套给所有动作。
- 当前 Demo 的小绿 Reload → Idle 使用 0.1 秒固定混合，是适配当前状态图的平滑设置，不宣称它就是原版换弹后的完整状态逻辑。
- 爱丽丝刹车的快速甩裙、女仆桃井跑步裙摆的循环接缝可追溯到原资源；按保留原动作的决定未修改关键帧。临战爱丽丝两类战场 EX 结束未复现同类大幅衣摆突跳。

本轮没有新增运行时脚本，也没有修改原动作关键帧。复查时 Unity Console 无警告、无错误，已退出 Play。这里记录的是动画切换检查，不代表全部角色 EX 的音效、特效、命中和渲染已完成验收。

此前同一 Demo 已补接普通爱丽丝开火事件与普攻命中特效、队长入场语音、提起与单选移动语音、四段血条和六张横排技能卡。编队曝光单独调整为 -0.3 EV，不套用到战场；女仆柚子 EX 的脸部异常高光按实际灯光绑定与原光方向曲线修复。

## 启动和版本控制

直接预览用 `Player_GameDev.unity`；检查资源更新与完整启动链时用 `Assets/Boot.unity`。启动入口为 `Assets/GameScript/Runtime/Bootstrap/Entry/Boot.cs`，实际运行模式以 Boot Inspector 为准。默认服务器为 `https://gtuantuan.online:9444`，仍读取现有服务器配置。当前依赖为 YooAsset 3.0.6、HybridCLR v9.0.3，以 `Packages/manifest.json` 为准。

修改 AOT 代码需要重新构建播放器；修改热更逻辑后需要重新生成对应 DLL 与资源包，不能把编辑器 Play 通过当成 IL2CPP 发布验证。已有 StreamingAssets Preload 包是整套构建产物，不应只更新 version 而遗漏 catalog 和 bundle。

动画文件通过 Git LFS 管理；克隆后需安装 Git LFS 并拉取 LFS 对象，不能把文本指针当成动画导入 Unity。截图、捕获视频、Library、临时文件与个人 UserSettings 不纳入本次提交。此次仅本地提交，不自动推送服务器。

当前 Unity MCP 是编辑器工具，本机包路径为 `C:/UnityProject/unity-mcp-beta/MCPForUnity`。在另一台电脑恢复工程时，需要安装对应工具并调整该本地包引用；它不是角色运行时资源依赖。

搜刮、背包、完整经济与永久存档仍属后续阶段；临战支援的第二、第三次触发尚不能算已验收，失败直升机救援尚未确认实现。继续开发时依据两份 v0.3 文档推进，不沿用旧的单角色脚本与旧场景路径。
